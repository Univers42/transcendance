# 🤝 Code of Conduct

## Our Pledge

We as team members pledge to make participation in our project a **harassment-free, productive, and respectful experience** for everyone, regardless of background, experience level, or personal identity.

We are a team of 42 students working toward a shared goal. Our success depends on trust, clear communication, and mutual respect.

---

## Our Standards

### ✅ Expected Behavior

- **Communicate openly** — share blockers, progress, and concerns early
- **Be respectful** — disagree on code, not on people
- **Give constructive feedback** — in code reviews, focus on the code, suggest improvements, explain your reasoning
- **Take responsibility** — if you break something, own it and fix it
- **Help each other learn** — explain concepts when a teammate is stuck, don't just hand them the answer
- **Meet your commitments** — if you say you'll deliver X by Friday, deliver it or communicate early if you can't
- **Document your work** — code without context is a burden on the team
- **Be on time** — for standups, reviews, and deadlines

### ❌ Unacceptable Behavior

- Dismissing or belittling a teammate's contribution
- Passive-aggressive communication (or silence when communication is needed)
- Pushing directly to `main` or `develop` without a PR
- Taking credit for someone else's work
- Ghosting — disappearing without communicating
- Submitting AI-generated code you can't explain
- Refusing to participate in code reviews

---

## Roles & Accountability

| Role | Accountability |
|------|---------------|
| **Product Owner** | Defines priorities clearly, validates work, communicates with evaluators |
| **Project Manager** | Ensures team syncs happen, tracks deadlines, flags risks |
| **Tech Lead** | Maintains code quality, reviews architecture decisions, enforces standards |
| **All Developers** | Write code, test it, document it, review teammates' PRs |

> **No one is exempt from code review.** Even the Tech Lead's code gets reviewed.

---

## Conflict Resolution

Conflicts are normal in team projects. Here's how we handle them:

1. **Talk directly** — Raise the issue with the person involved, respectfully
2. **Escalate to the team** — If unresolved, bring it to the next standup for group discussion
3. **Seek external help** — If the team can't resolve it, consult a 42 staff member or peer mediator
4. **Document the outcome** — Record what was decided so it doesn't come up again

---

## Enforcement

Team members who violate this code of conduct may face:

1. **Private conversation** — A teammate or PM reaches out to discuss the issue
2. **Team discussion** — The behavior is addressed in a standup
3. **Role reassignment** — Persistent issues may result in adjusted responsibilities
4. **Escalation to 42 staff** — As a last resort for serious or repeated violations

---

## Scope

This code of conduct applies to:
- All project repositories and branches
- Team communication channels (Discord, Slack, in-person)
- Code reviews and pull request discussions
- Standups and planning sessions
- Project presentations and evaluations
